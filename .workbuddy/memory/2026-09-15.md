## 修复「Expected ',' or ']' after array element in JSON at position 16041」（GEO 调优报错）

- 根因：`.env.production` 的模型已换成 **deepseek-v4.1-flash（推理模型）**，思考 token 计入输出上限 `max_tokens=16384`；长文 GEO 调优时「思考 + 正文」超限，JSON 在约 16041 字符处被拦腰截断 → `JSON.parse` 报错。
- 容器内实测（写 `scripts/_ai-diag*.js` 后删）：50 项生成任务基线推理吃 6114 token、耗时 48s；`thinking:{"type":"disabled"}` 推理归零、19s、JSON 正常；`reasoning_effort=low` 和 `enable_thinking=false` 无效；`max_tokens=32768` 中转站接受。
- 修复（提交 `f28fa53`，已推送并部署）：
  1. `generateJson` 默认带 `thinking:{"type":"disabled"}`，遇 400 自动回退普通请求；`AI_ENABLE_THINKING=1` 可恢复思考。
  2. 服务器 `.env.production` 追加 `AI_MAX_TOKENS=32768`（默认仍是 16384，示例文件已更新注释）。
  3. 新增 `finish_reason=length` 检测 → 明确报「AI 输出被截断…请调大 AI_MAX_TOKENS」。
  4. JSON 解析失败时打 `[ai]` 日志：content_len、finish_reason、usage、出错 position 及前后 120 字符片段，下次可直接看 `docker compose logs` 定位。
- 验证：本地 mock 三场景（正常流式 / thinking 被拒回退 / 截断）全过；`tsc` 与 `next build` 通过；服务器 md5 一致、重建后产物含 `AI_MAX_TOKENS`/`thinking`/「输出被截断」，容器 Up、站点 307。
- 遗留观察：`docker compose logs` 里有与 AI 无关的 Next.js 报错 `TypeError: Cannot read properties of null (reading 'message')`（app-page runtime），来源待查。
