## 修复「AI 生成超时（120 秒）」

- 现象：线上 http://106.75.232.103:3000/ 生成平台版本/润色时提示「AI 生成超时（120 秒），文章较长时请稍后重试」。
- 定位：报错字符串唯一来源 `src/lib/ai/anthropic.ts`，由应用内 `AbortController` 120 秒定时器触发；非网络问题（站点 307 / 24ms，api.modelverse.cn TLS 33ms），非 API Key 问题。
- 根因：`generateJson` 为非流式一次性生成 + `max_tokens: 16384`，长文生成超过 120 秒被本地中断；SDK 默认 `maxRetries: 2` 进一步消耗预算。
- 改造：`generateJson` 改为 `stream: true` 累积 `delta.content`；用「停滞超时」替代固定总时长。
  - `AI_STALL_TIMEOUT_MS` 默认 90000（连续无新 token 才判失败）
  - `AI_TOTAL_TIMEOUT_MS` 默认 600000（兜底上限）
  - OpenAI 客户端设置 `maxRetries: 0`
- 关键坑：OpenAI SDK 在中止时会**静默结束流**而不抛错，必须在 `for await` 循环**结束后**再检查一次 `controller.signal.aborted` 兜底，否则会误报成「AI 返回内容不是 JSON」。
- 验证：本地 mock SSE 服务跑通「正常流式拼接」与「停滞超时中止」两条用例；`tsc --noEmit` 与 `npm run build` 均通过。
- 同步更新：`.env.example`、`.env.production.example`、`DEPLOY.md`（新增第 8 节超时排查手册，含服务器 curl / 容器内 Key 验证命令）。
- 变动文件：`src/lib/ai/anthropic.ts`、`.env.example`、`.env.production.example`、`DEPLOY.md`（4 个文件，+119/-17）。
